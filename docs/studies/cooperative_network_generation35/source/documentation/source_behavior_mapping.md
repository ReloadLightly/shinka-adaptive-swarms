# Primary source behavior: decision and implementation mapping

The user's precedence amendment selects **`source_executable` as the primary behavioral reference** at upstream commit `b3d7737613578da260fee561b6f73122dc4f2ab0`. `paper_directed` remains a separately named sensitivity interpretation. The choice follows the stated priority of fidelity to preserved executable behavior; it does not depend on which interpretation produces higher utility or agrees better with a published qualitative pattern. Partial results already existed when this amendment was made, so it is not described as a choice registered before any observations.

The authority receipt and this mapping are bound by hashes in `experiments/paper_trajectory_v2/analysis_decisions.json`. A valid binding makes source/prose precedence and unavailable historical grid/seed metadata disclosed methodological choices for v2. It does not establish which unavailable production program or seeds generated the publication. Neither agreement between the two tracks nor recovery of historical seeds is required by this precedence choice.

This document records existing implementation and previously executed checks. No engine, reference cases, trajectory, scalar result or model call was changed or rerun to prepare it.

## What is preserved in the primary track

| Behavior | Pinned source | V2 source implementation and confirmation |
|---|---|---|
| Actor scheduling | `GamePlayerAgent.step` shuffles the complete actor list once, then visits every actor once per round. | `PaperSimulation.round`, source branch, calls the inherited shuffle and one `act` per actor. The existing source-equivalence fixture compares every round's adjacency and RNG state. |
| Invocation of noise | Each visited actor draws its random/strategic branch independently with probability p; a random turn calls `GamePlayerAgent.randomTie`. | `referenceAct` draws `random.nextBoolean(noise)` once for the source activation and delegates the random move to the unchanged controller. Thus p is an action-branch probability in the primary track. |
| Addition and deletion search | `Agent.bestAdd(m)` uses replacement draws with m opportunities per layer, including wasted candidates; `bestDrop` scans existing deletion opportunities. | The source reference calls these inherited methods unchanged. Source ordering, strict comparisons and draw consumption are retained. |
| Swap search | `Agent.bestAddDropCombo(m)` retains its deletion-layer counter across candidate additions. This limits the actual deletion search to the first eligible addition. | `PaperAgent.bestAddDropCombo` delegates directly to `super` for `SOURCE_EXECUTABLE`. The primary track preserves this behavior rather than correcting it to fit prose. |
| Action ordering | The source compares add, drop and swap in its existing order. A successful swap can be followed by the independent final deletion. | `referenceAct` preserves the source branch ordering and possible second old-edge deletion. The paper sensitivity uses a different, explicitly declared rule. |
| Recipient acceptance | `Agent.addTie` accepts a strictly beneficial offer without a random draw; otherwise it draws with probability p. The short-circuit evaluation order matters. | `ReferencePolicy.accept` delegates to `Offer.originalAcceptance`: strictly higher hypothetical utility returns deterministic acceptance; otherwise the offer handler makes the stochastic draw. Exact RNG-state checks include these calls. |
| Ties and utility arithmetic | Strict comparisons, source tie ordering and the original utility expression/arithmetic order are retained. | Utility caches are checked bitwise against unchanged `AgentsSimulation.utility` for existing graphs and hypothetical additions, deletions and swaps. The engine adds no comparison epsilon. |
| Seed policy delegation | The seed is a separate all-actor policy object that invokes the reference turn and acceptance. | The compiled `CandidatePolicy` seed is compared with `ReferencePolicy` on topology, cumulative utility and RNG state throughout the existing source-equivalence fixture. |

## Declared protocol choices outside behavioral equivalence

The v2 protocol records the empty network and every integer time through t=100, applies the shock immediately after the t=50 observation, and uses separately seeded external shock identities. Original native equilibrium stopping is disabled. The preserved executable's default main instead enables p=.75, times 200/400, and partial-shock selection from its action RNG. The source-equivalence fixture therefore compares the same explicit timing and recipient overrides in both implementations. **Exact behavioral equivalence under those overrides is not an untouched replay of the original batch main.** See the existing [engine contract](../java-paper/ENGINE_CONTRACT.md).

The six-value d/e grid and five repetitions were declared from retained source loops; the four fixed-noise variants and paper measurement times were declared before v2 case execution. V2 supplies its own recorded seeds. Missing historical seeds, exact production grid and repetition metadata remain historical limitations. Under the explicit user precedence decision, recovering them is not a prerequisite for using the preserved executable as the primary v2 baseline. The full already declared reference matrix remains required; it is neither reduced nor retrospectively tuned.

## What this amendment does not clear

The actual dormant source-smart defect remains a numerical/behavioral blocker for its declared track: see the retained [N40 self-proposal evidence](https://github.com/ReloadLightly/shinka-cooperative-network/blob/42ccaaf4b4f9c361f671cf54b6d874bc4d442359/docs/paper_trajectory_v2/source_smart_n40_diagnostic.json). The amendment does not make that defective method a supported smart-search reference, silently repair it, or discard its pending cases. Missing declared reference executions remain missing.

Equation7's unidentified published mixed-effect specification, exposure/CDF reconstruction choices, the S1 caption inconsistency, and other separately recorded analysis questions remain subject to their own evidence and decisions. Selecting a primary behavior does not automatically resolve them. A figure-direction or table-moment difference is still reported honestly; any assessment that a particular discrepancy is nonblocking requires its own explicit, evidenced review. The report must retain primary and sensitivity results separately and must never turn an interpretation difference into an evolved-policy gain.

The [source recheck](https://github.com/ReloadLightly/shinka-cooperative-network/blob/42ccaaf4b4f9c361f671cf54b6d874bc4d442359/docs/paper_trajectory_v2/scheduling_source_recheck.md), [history appendix](https://github.com/ReloadLightly/shinka-cooperative-network/blob/42ccaaf4b4f9c361f671cf54b6d874bc4d442359/docs/paper_trajectory_v2/controller_history_appendix.json), and previous checkpoint reports preserve the earlier ambiguity and discrepancy evidence. The precedence amendment changes the prospective methodological choice; it does not rewrite that evidence.
