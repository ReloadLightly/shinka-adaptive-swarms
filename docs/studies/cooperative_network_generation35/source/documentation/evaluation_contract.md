# Amended extension contract and interruption handling

The [active scientific contract](../experiments/paper_trajectory_v2/scientific_contract.json) is frozen under the explicit execution amendment, before descendants. The [amended readiness](https://github.com/ReloadLightly/shinka-cooperative-network/blob/42ccaaf4b4f9c361f671cf54b6d874bc4d442359/experiments/paper_trajectory_v2/discovery_readiness.json) requires the complete1,152-case N40/random/rep0 comparator block and its one globally chosen288-case development panel. Remaining reference repetitions, N100 and full-paper reporting are deferred and are not claimed complete. Full valid seed admission remains mandatory before model calls. Source-executable semantics stay primary, with paper-directed semantics retained as sensitivity. See the [exact freeze summary](https://github.com/ReloadLightly/shinka-cooperative-network/blob/42ccaaf4b4f9c361f671cf54b6d874bc4d442359/docs/paper_trajectory_v2/amended_discovery_freeze.md) for current selection, scaling and timing.

`paper_trajectory_v2.evaluate.verify_contract()` requires `paper-extension-contract-v1`, its canonical `identity_sha256`, and a `files` map containing all required artifacts. It explicitly binds `evaluate.py`, `runtime.py`, `design.py`, `gate.py`, `policy_guard.py`, `native.py`, `recovery.py`, the recovery launcher, the current `compiled_guard_identity`, evaluator SHA, engine SHA, reference-policy source SHA and complete-reference milestone identity. The exact user decision at `experiments/paper_trajectory_v2/primary_reference_decision.json` is required (file SHA256 `6070d9f9e7ee98bc1c6791279626921ab21d1cae860f37d6c92764866adb47e3`, identity `fc3fa6fe30970f98aed5c732870c02d66b3bae112ff4b47f04104e12cbbf68d3`). The manifest must register that same path/hash/identity under `scientific_contract_decisions.primary_reference`, and the contract must name and freeze it plus its existing equivalence evidence. Primary remains `source_executable` at upstream `b3d7737613578da260fee561b6f73122dc4f2ab0`; `paper_directed` cannot become the optimization environment by changing a coverage label. The coverage-choice receipt also binds that primary-decision identity. The prepared seed and immutable task source must match their actual search copies. The development panel, baseline, coverage, scientific decision and timing paths are mandatory frozen artifacts. Baselines must equal the actual saved cache receipts, with matching engine/program/case/cache identities, finite utility and frozen trajectory hashes.

The coverage artifact has schema `paper-extension-coverage-v1`. It declares the unchanged six-value incentive grid, the user-selected `source_executable` primary interpretation, one fixed sampling comparator and one fixed reference-noise comparator. Neither noise nor sampling is multiplied into evolved external conditions. `development` declares populations, repetition IDs, split and the exact `case_map` (case ID to canonical case SHA). The validator regenerates all36 independent incentive pairs times all eight numeric cost/shock/control cells for each population and repetition; no omitted, duplicate, changed-seed or extra-variant cases pass. Main N40 coverage is mandatory. Under the registered execution amendment, N100 has explicit `deferred_by_execution_amendment` status and is not a prerequisite; the validator requires exactly population40, repetition0, reference split, random sampling and equal1/288 condition weights. The earlier broader contract path remains available only with its explicit development/confirmation declarations. In that path the separately declared `n100_robustness` records populations `[100]`, repetition IDs and a scope of development or confirmation. Development scope requires a full exact panel path, split and case map matching the evaluated N100 subset. Confirmation scope permits only a public protocol and its SHA256; actual case paths, case maps, splits and seed material are rejected. Choosing that scope is still a scientific decision, not a choice made by this repair.

Confirmation uses the public protocol schema `paper-post-selection-confirmation-v1`: the complete grid times eight numeric conditions, predeclared repetitions, `sha256-post-selection-nonce-v1`, a256-bit nonce created only `after_selection_frozen_and_discovery_stopped`, a `separate_confirmation_stage`, and discovery access `protocol_only`. Its `protocol_sha256` hashes the canonical protocol dictionary. Discovery validates this dictionary without creating or opening confirmation cases. It checks consumed scientific artifacts explicitly rather than reading every arbitrary entry in a file map. Headless read-only repository access is **not** a confidentiality boundary; a different public split string in `seed_for()` is also not a held-out design. No confirmation seed material or case file exists or is generated by these checks.

The separate future confirmation stage must first freeze selected program and comparator identities and verify discovery/provider processes have stopped permanently for this selection. Only then may it draw a fresh32-byte cryptographic nonce. The named derivation hashes canonical `["sha256-post-selection-nonce-v1", nonce_hex, coverage_sha256, N, d, e, repetition, stream]`, where stream is `dynamics` or `shock`; the first15 hexadecimal digest digits become the corresponding nonnegative engine seed. Cost/shock/control variants retain common history seeds. The confirmation receipt must bind the frozen selection/comparator hashes, protocol/coverage hashes, nonce SHA256 and exact generated case map. Raw nonce and resulting cases belong to the separate confirmation stage and must never be supplied to a resumed discovery process. This launcher, discovery-closure enforcement and fresh-seed generator are still **unimplemented and unexecuted**; this repair creates neither fresh seeds nor a claim of sealed held-out data.

`scientific_decision_path` must record `frozen_before_discovery`, zero descendants at freeze, the coverage SHA, a justification and evidence. Condition IDs include only N, both incentive values and numeric cost/shock settings. Derived history IDs cluster cases sharing dynamics/shock seeds; labels are not inserted into runtime case payloads, allowing exact existing reference-cache reuse when a frozen development declaration deliberately uses reference histories. The scale must be finite and positive. Weights must be finite, positive, sum to one and cover every external condition. Feedback reports trajectories and history-seed families instead of falsely describing related cases as independent.

The timing artifact has schema `paper-extension-evaluation-timing-v1`, exact development-panel SHA, one numerical worker, an exact `case_upper_seconds` map, positive startup/finalization allowance, budget basis (`measured_upper_bound` or `predeclared_upper_bound`), justification and frozen evidence paths. Every case budget must fit the declared per-case timeout; their sum plus startup/finalization must fit the full-panel `evaluation_timeout` in HH:MM:SS. Model/proposal and checkpoint draining allowances are explicit positive contract fields and must match the timing artifact. `evaluation_admission_seconds(contract)` returns full evaluation timeout plus `model_and_proposal_drain_seconds` and `checkpoint_drain_seconds`; the controller must reserve that bound before admitting a batch. No five-minute full-panel default or convenient subset is supplied.

Only explicit policy-source/compiled-guard violations, source-located Java compilation errors, or a supported Java runtime exception with a candidate stack frame are classified as candidate invalidity. Unknown runtime errors, corrupt caches, missing files, contract drift and ambiguous timeouts are infrastructure interruptions. Each evaluator failure gets a distinct retained evidence file with source hash, stage, traceback, completed cache keys and partial effects. Infrastructure failures emit an interruption marker and the established campaign `infrastructure-pause.json`, return4 and provide no numeric fitness. Existing receipts are retained. Repeated invocation cannot overwrite a completed or interrupted evaluation.

The v2 native adapter checks interruption markers before persistence and side effects. It also creates a pause for missing/corrupt terminal outputs, covering an evaluator killed before it can write its own receipt. Such an accepted proposal remains absent from the population and reward updates; it retains `accepted-job.json`, candidate source, parentage, attempts, output logs and case cache. Initialization insertion is separately guarded against native's fallback that assumes a failed zero-score seed is correct. Constructor, proposal/submission and resume checks reject unresolved infrastructure evidence. At a drained infrastructure boundary, the adapter also signals native finalization explicitly: the unchanged generation target cannot provide that signal for an accepted slot with no terminal fitness. The actual pinned-native mocked fixture verifies exit without inventing a completion or reward; its [failure/pass receipt](https://github.com/ReloadLightly/shinka-cooperative-network/blob/42ccaaf4b4f9c361f671cf54b6d874bc4d442359/results/paper_trajectory_v2/operations/native-pause-lifecycle/receipt.json) retains the earlier hang evidence.

Recovery is deliberately **not automatic**. The separate [accepted-evaluation recovery command](https://github.com/ReloadLightly/shinka-cooperative-network/blob/42ccaaf4b4f9c361f671cf54b6d874bc4d442359/docs/paper_trajectory_v2/accepted_evaluation_recovery.md) now verifies an evidence-bound operator resolution under the campaign lock, journals before archival, and replays only the saved accepted descendant source with target `generation + 1`. Ordinary admission remains blocked by any pause or recovery journal. Source/lineage/cache/native identities, unchanged arm pulls and one exact saved-arm outcome/reward are checked. The path is covered by an actual pinned-native mocked lifecycle; no real recovery has run. Seed initialization, prepared-only proposals, and reconciliation after a crash or interruption inside the recovery operation remain unsupported and explicitly blocked.
