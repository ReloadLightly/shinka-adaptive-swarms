# Research and execution contract

Build a cumulative scientific study of adaptive multi-swarm search based on Blackwell,
Branke and Li (2008), using the pinned DEAP source and native ShinkaEvolve.

- Read README.md and docs/reproduction.md, then inspect actual run artifacts before continuing.
- Reconstruct the mechanisms, record deviations, and proceed to actual program evolution.
  Missing historical seeds or nonessential parameter details do not forbid a documented reconstruction.
- Preserve completed runs. Store each new run in its own directory and checkpoint each completed case.
- Keep source fidelity, execution success, optimizer performance, and scientific discovery distinct.
  Do not count a corrected upstream bug as an evolutionary improvement.
- Use the user's requested Astra/Ultra mode for supervising Codex when available. Log actual
  model and supported effort for Shinka's internal mutation calls separately. Never relabel settings.
- Use subscription-authenticated Codex for model calls. No paid API fallback is authorized.
- Show flushed, timestamped terminal progress plus persistent logs. Include the current activity,
  case/proposal identity, completed work, elapsed time, outcomes and errors. Heartbeats describe
  waiting honestly; they do not imply model-token streaming or hidden reasoning access.
- Use the native Shinka WebUI on the actual database. Supply terminal/WebUI launch commands.
- Execute candidates, retain program lineage and explanations, compare against a competent
  corrected baseline at equal evaluation budgets, then test promising behavior on fresh cases.
- Keep benchmark internals and held-out inputs out of candidate observations. Count change
  detection and memory reevaluations as objective evaluations. Use separate environment RNGs.
- Run checks that resolve concrete implementation/scientific risks. No arbitrary host-memory
  reserves, mandatory exact-result gates, unrelated campaigns, or blanket reruns.
- Update README and figures from observed data; label illustrative 2D views separately from
  the 5D experiment. Publish authorized work and verify the remote commit.
- Do not commit credentials, raw authentication files, or the copyrighted uploaded book.
