# Native search continuity and reference gate

`paper_trajectory_v2/native.py` composes the existing operational wrappers around pinned native Shinka. It opens only the new campaign's configured search directory. No v1 program, reward, prompt, recommendation, archive or case outcome is imported. `native-task-identity.json` binds the scientific identity, executed seed and immutable/search prompts, native settings and evaluator configuration. Foreign or unqualified bandit/memory state is rejected.

The configuration starts with three native islands, a fitness archive of64, weighted parents, native archive/top inspiration, diff/full/crossover probabilities .5/.3/.2, three resamples/patch/novelty attempts, local embeddings and native novelty, asymmetric UCB with Astra xhigh and Sol xhigh and monetary cost weight0, migration every10 generations at .1, and dynamic islands at stagnation20. Native meta recommendations and prompt evolution use Astra xhigh at intervals10, with prompt percentile refresh20. Weighted selection instead of beam search, and fitness archive selection instead of crowding, are explicit alternative choices. W&B, SLURM, Docker and oversubscription remain disabled; local sequential admission supports bounded draining and exact accounting.

Before initialization, one reference seed must be explicitly evaluated and verified to have score0. Its two native island copies are administrative rows, excluded from the descendant budget, UCB rewards, and prompt/meta observations. Generations1–50 are descendant proposal slots, including terminal failures. Provider responses, patch/resampling/novelty attempts, evaluated programs and numerical trajectories remain separate counts. Native zero/negative improvement handling is retained; it is a selection rule, not evidence of scientific improvement.

The bandit retains native reward and RNG state with a v2 identity extension. Meta and prompt state retain exact processed-program IDs, pending programs, recommendations, prompt fitness and lifecycle counters. An ambiguous in-flight memory operation fails closed. An interrupted unaccepted generation also requires reconciliation before a new proposal; its saved evidence is preserved. Administrative copies and migration receipts use the existing scoped hooks. Legacy `phase-b-*` telemetry filenames describe the reused storage schema only; they contain new-task state. SQLite random ordering and UUID generation prevent a claim of bit-identical replay.

The focused test `tests/test_paper_native.py` uses actual native databases, island copying, asymmetric UCB, meta analysis and prompt evolution with mocked provider replies and a synthetic scalar evaluator. It passed on2026-09-17 in6.457s: zero initial trials, three islands/two copies, negative and positive descendants, three synthetic evaluations/two mutation responses, persistence across one-slot restarts, no repeated completed work, foreign-state rejection and the fixed51-slot ceiling. These are infrastructure checks, not research trajectories or subscription calls. The process required local asyncio socket wakeups unavailable in the restricted tool sandbox; it passed outside that sandbox without network/model use.

`paper_trajectory_v2/gate.py` requires the complete declared34,560 reference trajectories and the frozen source-to-code-to-output-to-publication report for Figures2–7, TableS1 and FiguresS1–S4. It verifies exact case/cache/trajectory/engine/reference-source identities, all retained primary sources, the behavior contract and reference normalization artifacts. Counts or implementation labels alone cannot pass. Missing methods or consequential unresolved discrepancies block discovery. The gate never fabricates a milestone or narrows the matrix to fit a session. Four focused gate checks cover unfinished evidence, changed science, foreign case identity and consequential discrepancies.

The prospective compiled-code guard now runs on both fresh compilation and cached reuse. Its positive seed integration receipt is linked from [native integration status](native_integration.md), which also lists the remaining extension contract, evaluation-validation and seed-verification work. Compilation is not numerical seed verification; the complete-reference gate still blocks native initialization and all inference.

Prospective evaluation interruption handling now refuses native ingestion and automatic accepted-job resubmission when an interruption marker or missing/corrupt terminal output is present. Source, lineage and exact-case receipts remain available for the separate [explicit accepted-descendant recovery operation](https://github.com/ReloadLightly/shinka-cooperative-network/blob/42ccaaf4b4f9c361f671cf54b6d874bc4d442359/docs/paper_trajectory_v2/accepted_evaluation_recovery.md). Ordinary resume cannot consume its pending journal. Initialization/prepared-only states and interrupted recovery operations retain an explicit review boundary.
